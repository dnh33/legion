# Security policy

## Supported versions

Legion is young. Only the latest release on the default branch receives security fixes.

## Reporting a vulnerability

Please do not open a public issue for a security problem. Use GitHub's private vulnerability reporting instead: open the **Security** tab of this repository and choose **Report a vulnerability**. Include what you found, how to reproduce it, and the impact you expect. You can expect an acknowledgement within a few days.

## Threat model

Legion is a personal, local tool. It is not designed to be exposed to a network or shared between users.

- **Local-only binding.** Legion Core listens on `127.0.0.1` only. Do not proxy it to other machines.
- **Two secrets.** The MCP token in `config.json` lets Claude Code and Cowork run and read agents; it cannot approve, accept notes, change settings or touch BSV. The admin secret exists only in memory while the Legion app is open. This stops a bot with a Bash tool from reading a file and approving its own request. It does NOT stop a process running as your Windows user from reading Legion's memory, editing its installed files, or talking directly to your BSV wallet on 127.0.0.1:3321. Only a VM or a separate OS account stops that. Every BSV spend is still confirmed in your wallet.
  - The **MCP token** (`authToken` in `config.json`, mode 0600) is accepted on `/mcp` and on a short client list only: `GET /api/state`, `/api/agents`, `/api/catalog`, `/api/tasks/:id` (and `/wait`), `POST /api/tasks`, `POST /api/tasks/:id/cancel`, and the event stream `GET /api/events`, which also accepts `?token=` because browsers cannot set headers on `EventSource`. Treat it like a password: anyone with it can run your agents, but only under the `ask` ceiling below.
  - The **admin secret** is made fresh by the Electron app each time it starts its core (24 random bytes), handed to that core over its stdin pipe, and kept in memory: never in an environment variable, argument, file or log, and never in `/health` (which only says `admin: true` or `false`). The app window sends it as `X-Legion-Admin`. Every other route, including every `/api/kg/*` route (reads too), rooms, BSV, settings, agent edits, approvals, VM routes, config, doctor and any path Legion does not know, needs it. The gate runs before routing, so an unknown path answers 403, not 404. The secret is compared in constant time.
  - A core started without the app (for example by the MCP stdio bridge for Cowork) has no admin secret, so its admin routes are closed to everyone (`403 admin_unavailable: open the Legion app`). When you open the app it stops an idle core of that kind and starts its own; if that core is busy it asks first. The dev UI served with `?token=` is read-only for the same reason.
- **Tasks the token starts are capped.** Anything started through `/mcp` (`legion_run`, `legion_continue`) or `POST /api/tasks` without the admin header runs under an `ask` approval ceiling, whatever the agent is set to: an agent set to `full` runs in `default` mode and its shell commands and edits wait for your card, which says "Asked by an MCP client". Continuing such a task keeps the ceiling (and any earlier origin and taint). `legion_create_agent` makes `ask` agents. Notes such a run writes to the shared Library wait in the Inbox until you accept them. Starting a task from the app window itself is the only way to get an unrestricted run.
- **Credentials.** Legion never reads or stores your Claude account credentials. In the default mode it relies on the account Claude Code is signed in to. If you choose `api-key` mode, the key is stored in `config.json`; boat.dev API keys are too. Keep that file private.
- **Known limits (same-user attacks).** The two-secret split stops the easy attack: a bot with a Bash tool reads `config.json` and calls the API as you. It does not stop a process that runs as your operating-system user and is willing to attack Legion itself: it can read the memory of the Legion app or its core (a debugger or `ReadProcessMemory`, `ptrace` on Linux) and take the admin secret, synthesize input to the window and click Allow, edit the installed JavaScript and wait for the next launch, stop Legion and run its own core, read `~/.claude` credentials, or call your BSV wallet on `127.0.0.1:3321` directly, which no Legion code sits in front of. `config.json` also still holds `boat.apiKey` (and the Claude API key in `api-key` mode) in plaintext, and any agent's Read tool can read it without a card. Only OS isolation stops these: run Bash-capable agents in a boat.dev VM or under a separate operating-system account, and do not give a Bash tool to an agent that reads untrusted web content. Every BSV spend is still confirmed in your own wallet. A scoped per-run token, DPAPI or a named pipe were considered and add nothing against a same-user attacker. See `docs/LIBRARY.md`.
- **Known limits of the Library's safety rules** (the full list is in `docs/LIBRARY.md`): the same-user limits above; seed-phrase detection knows only the English BIP-39 list and is a guard against mistakes, not against a bot hiding a secret; taint follows file tools only (a tainted run's Bash-made or copied files are not tracked) and the tainted-path list is a file a same-user bot can edit; a plain new file a bot planted in a vault you then import becomes your note, and a file you imported earlier that a bot rewrites updates in place on the next import; the lock file protects processes on one machine only.
- **Agents run code.** Approval modes (`ask`, `auto-edits`, `full`) control what an agent may do on your machine without asking. `full` disables prompts for that agent. Use VMs for untrusted work.
- **Renderer.** The Electron window is sandboxed with context isolation and no Node integration.

Reports about these boundaries (for example an authentication bypass, a way to reach the API from a web page, or a secret leaking into logs or API responses) are in scope.
