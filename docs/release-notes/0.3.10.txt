This update installs from inside Legion.

Your agents are no longer stopped by what they read
Before, an agent that had read a web page, a GitHub comment or a file from outside your project could not assign or delete board items, write working memory or share notes directly. Now it carries on as normal. What it creates carries a label, and the next run is told when its working memory came from a run that read outside text. Money confirmations, GitHub write cards, the stop for disastrous commands and your Block rules work as before. A trigger tag from such a run does not fire on its own; it waits in your Inbox, and only a note you wrote or edited yourself can fire.

Running a program never marks a run
node -e, make, go test, npx, npm install, git pull and programs Legion does not know leave an agent clean. Only text that comes in from outside marks a run: the web, GitHub text you read, other tools and files outside your project.

The board works the way you build
An item an agent wrote is routed by the Marshal like any other, and your Run button runs it as you set the agent up.

You stay in control
Settings, Gates, Outside text, Strict keeps every lock from 0.3.9, marks every shell command and keeps the approval card for web access after a run read GitHub data. Nothing needs migrating.

Smaller fixes
After a good update, Settings, About shows one line with a Show steps button instead of the whole list. The GitHub area now says that each agent needs its own write access, and the refusal an agent gets says where to give it.

One thing to know
A test script that fetches a web page by itself does not get a label. In a repository you do not trust, choose Strict.
