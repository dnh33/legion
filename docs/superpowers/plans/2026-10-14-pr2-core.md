# PR 2 Core: queue truth and ask policy, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax.

**Goal:** The core half of 0.3.0 "Runs without you": queue reasons on the wire, per-project ask policy (wait, quiet hours), pause new starts, budget and spend ledger, consequence classifier, attention counts. No new screens.

**Architecture:** Pure shared modules (`consequence`, `attention`, `ask-clock`, `away-copy`, `spend-periods`) feed a new core module `src/core/away/` (policy store, ledger, attention tracker, routes). Brokers and the engine get optional hooks (`AskPolicy`, `AwayHooks`). Every hook absent means today's behaviour.

**Tech Stack:** TypeScript (NodeNext), node:test on `dist/test`, Claude Agent SDK 0.3.285.

**Spec:** `docs/superpowers/specs/2026-10-14-runs-without-you-design.md` (sections 2, 4.1 to 4.10, 5, 9.1, 10 "PR 2").

## Global Constraints

- Defaults: deny at 10 min, not paused, no budget, notify "problems", quiet off. Absent policy = today.
- No timer path ever resolves an ask to allow (spec 5.1). Unknown consequence = level 3, `certain:false` (5.3).
- All new routes admin-only (no entry in `CLIENT_ROUTES`); a bearer token gets 403 (5.9).
- Away store can only restrict (4.1); the away dir is a `protectedPaths()` entry (5.5).
- Notifications and attention carry no command text (5.8).
- Copy: no em or en dashes, say "your computer". No `Co-Authored-By` in commits. No outside product names.
- Local gate: `npm run typecheck` plus touched test files only (`npm run build:ts`, then `node --test dist/test/<file>.test.js`).

## Step 0 finding: SDK hook-timeout spike (spec 4.5 / 5.6)

Question: does the Agent SDK honour a long `HookCallbackMatcher.timeout`?

Evidence:
- `sdk.d.ts:963`: `timeout?: number` is "Timeout in seconds for all hooks in this matcher". `sdk.mjs` forwards it unchanged in the `initialize` control request (`hookCallbackIds`, `timeout`).
- Bundled CLI (`claude-agent-sdk-win32-x64/claude.exe`, 2.1.285) runs a callback hook with `timeoutMs = hook.timeout ? hook.timeout*1000 : default`. The SDK-callback path has no `Math.min` cap (the command-hook path does cap).
- Live probe against the real CLI (a `UserPromptSubmit` callback hook that waits 6 s; the run is cut right after):
  - `timeout: 2` -> hook signal ABORTED at 2.0 s (the value is applied, in seconds).
  - `timeout: 90000` (25 h) -> not aborted; the hook finished at 6.0 s.
  - `timeout: 3000000` (above 2^31 ms) -> not aborted at 6 s.
- Conclusion: long timeouts ARE honoured. Not proven: a wait of many real hours (not run). The engine clamps the hook timeout below 2^31 ms anyway.
- Decision: no fallback needed. Hook timeout = longest possible wait + 60 s, clamped. The park-on-quiet fallback is not built.

## Status and deviations (written at the end of the work)

- All 14 tasks done. Tests were written first and seen failing for the right reason (missing module or API) for tasks 1, 2, 3 (code moved aside), 6, 7, 8, 9 and 10. The away module (task 11) and the Marshal pause (task 12) had their code written before the tests; their tests were then proven with temporary mutations (an admin route moved to the client list, a leaked field in the attention view, the pause check removed) and each mutation failed a test.
- The spike changed nothing in the design: long hook timeouts work, so the quiet-hours wait is real (no park-on-quiet fallback).
- Park (spec section 6) is not built here (PR 5). The brokers accept `parkable` and `onPark`, nothing in the engine sets them, so a project set to "park" still waits and denies.
- The Marshal driver, when paused, still settles runs that ended; it only skips asking for and starting new work. The spec said "returns early"; this keeps the board truthful while paused.
- `createAwayCore` exists because the engine needs the away hooks at construction and the module needs the engine.
- The shared rig for the away tests is `test/away-rig.ts`.
