# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Markdown tables in chat replies.** GitHub-style tables (header row, a `|---|:--:|--:|` delimiter row with alignment colons, body rows) are drawn as a real, accessible `<table>` (column headers, a labelled scrollable region) instead of raw `| a | b |` lines. Escaped pipes (`\|`) and pipes inside `code` spans stay in their cell, short rows are padded and long ones cut, and without a delimiter row it is still plain text. A table is capped at 200 columns (a wider header is plain text) and 5,000 rows (the rest follows as plain lines). The parser stays linear (5,000-row and 2,000-cell cases are in the worker-timeout tests). **Copy as Markdown** is still the original source; **Copy as plain text** gives one line per row with tab-separated cells.
- **boat.dev VM fixes** (Zealot's report; see [docs/VM-NOTES.md](docs/VM-NOTES.md)). A free trial that refuses the `large` VM size no longer blocks an agent: Legion falls back to `default`, says so (record notice, tool result, Computer card) and remembers it for an hour; Builder is seeded with `default`. A failed or stale VM record is rebuilt from the agent's settings on the next start. `vm_stop` with no sandbox answers `{ok:true, stopped:false, message:"No sandbox to stop…"}` instead of a fake `error` state. boat.dev error codes get precise messages (`api_key_action_forbidden` names the action and says to create a full-access key; `trial_machine_class_not_allowed`; `provider_not_configured`), and the API key is scrubbed from error text. Saving a key probes what it may do (no sandbox is ever created) and shows the result in Settings, the Computer card and Doctor. `vm_claude` is hidden while Claude is known not to be set up on boat.dev, with an actionable message. VM tools report `runtimeSeconds` and `todaySeconds`; new read-only `vm_usage` tool and a usage line in the Computer card; a money estimate appears only when you set hourly prices (`boat.rates`) in Settings. Routes: `GET /api/vms/:id/usage`, `POST /api/boat/check`, `GET /api/boat/health`; `legion_vm` gains `usage`.
- **boat.dev VM fixes, review round**: usage is memoised; a stop waits for a start in flight (per-agent queue) instead of answering "No sandbox to stop", and a start after a stop waits for the stop; `vm_stop` asks boat.dev afterwards and reports the real state (`verified`, and `stopped:false` when the VM is still up); cached prices older than 10 minutes give "cost unknown" instead of an estimate; the key probe separates a rejected key from a dead network, a rate limit or a server error (no verdict on the key for those), and what it learned is dropped when the key changes or is removed, even for a probe still in flight; `vm_claude` is gated again when it is called, so it refuses before starting any VM; `boat/health`, `boat/check` and `vms/:id/usage` are admin-only and `/api/state` plus `boat.health` events give a token-only client a copy without prices or probe details.

- **Rooms and comms, round 2** (Zealot's real-use report and the New room bug).
  - **Per-task model for delegation.** `ask`, `tell`, `bot_send` and `room_post` take an optional `model` (`sonnet`, `opus`, `haiku`, `auto`; checked against the account's catalog when it can be read). It applies to that one task, is recorded on the task (`modelOverride`, a chip on the task tab and in Recent tasks) and on the room message (shown in the transcript and the export), and never changes approvals.
  - **Bots can ask for rooms.** New tools `room_create`, `room_add_member` and `room_remove_member`. Each shows you a card ("Zealot asks to create a room ... Members: A, B, C") that the tool waits for inside its handler, so no approval mode skips it. Rooms a bot creates are marked "created by <bot>", capped (config.json `comms`: members, default and maximum budget), start with the ordinary guards, and only you can delete them. Decision record in docs/COMMS-BRIDGE.md.
  - **Budget guard acts before the next turn.** A room used to pause after overshooting (observed: paused at $2.43 on a $2.00 budget). It now estimates the next turn (the dearest of the last 4, at least $0.02, plus turns already running) and pauses first, saying "paused before the next turn would exceed it".
  - **Review fixes (round 2 of this work).** Repeat suppression is now exact (same bot, same recipients, identical text) instead of fuzzy, so a legitimately different message is never dropped. A handoff always carries an explicit `@Name` and its receiving run wakes only bots it names with `@` (never the sender). A message you send to a room stopped on its budget is held and delivered when you resume (in memory, up to 20 per room), and a room budget is at least $0.05 (the UI, the API and `comms` config; the first turn of a room that has spent nothing always runs), so $0 or a negative number can no longer wedge a room. A per-task `model` is capped at the target agent's own setting (haiku, sonnet, opus; `auto` counts as sonnet), so `ask`, `tell`, `bot_send` and `room_post` cannot upgrade a peer to opus; the engine also clamps `/opus` prefixes in bot messages and skips the sonnet to opus retry for such tasks. A bot's room request is created exactly as the card showed it (re-checked when you answer; a changed room voids add and remove), and bot-supplied text on cards is flattened, stripped of markup and control characters, clipped and labelled as the bot's own.
  - **Handoff chatter stops.** A bot that hands off no longer wakes anyone with the rest of its turn, an answer to a handoff does not bounce back, and the exact same words to the same recipients by the same bot (inside one wake, or within 60 s while nobody answered) are stored once; the tools report `duplicate: true`.

### Fixed

- **Title bar crowding.** The BSV ticker ("TESTNET · knowledge mode / N bsv nodes") could be drawn over the Chat/Rooms/Library tabs at about 1440 px once the Doctor chip grew to "1 to fix": its slot was measured once and only re-measured when the whole bar resized. In windows of 1100 px or less the search box no longer moves when the Doctor chip changes. - **Blender approval card gutter.** A script that ends with a line break showed an extra empty numbered row (a 3-line script showed a line 4, and "4 lines"). A final line break now ends the last line instead of starting a new one; the other numbers are unchanged, so they still equal the line numbers in the safety check's findings (`\r\n`, lone `\r` and `\n` all count as before).
- **Typing in the New room dialog lost focus after one letter** (it jumped to the Close button, and a space then closed the dialog). The shared `Modal` re-ran its focus effect on every render because callers pass an inline `onClose`; it now runs once, prefers `[data-autofocus]`, and puts Close last. The same pattern fixed the autofocus of Room settings, New agent and the Library note dialogs. Check: `test-perf/ui-app/check-dialog-focus.mjs`.
- The Assayer stayed reachable while BSV mode was off through `legion_run`, `legion_continue` and `legion_vm` (including `exec`), and the error text named it; the same lookup now refuses it as an unknown agent, and the HTTP routes that start a task or drive the VM of a hidden agent answer 404.
- A plain re-seed of the BSV pack (the Lattice button, or toggling BSV off and on) overwrote human edits of pack nodes, and a human note written to scope `bsv` first stopped the pack from ever loading.
- A task's row in the UI could be replaced by an older snapshot (the answer to `POST /api/tasks` or `GET /api/tasks/:id` arriving after the events that followed it), leaving a finished agent shown as running. The row with the newer `updatedAt` now wins; within the same millisecond the more advanced state (running over queued, an end state over running) is kept.

## [0.1.0] - 2026-09-30

First public release.

### Added

- **Legion Core**, a local Node service bound to `127.0.0.1` with a bearer-token HTTP API, a server-sent events stream and an MCP endpoint.
- **Electron desktop app** with a tray icon, single-instance lock, sandboxed renderer, dark and light themes, and bundled fonts.
- **Agents** built on the Claude Agent SDK, using the Claude Code account you are signed in to (or an API key). Three defaults (Zealot, Builder, Scout) plus custom agents with their own system prompt, model, approval mode and working directory. Claude Code settings, MCP servers and claude.ai connectors are inherited, and extra MCP servers can be added in `config.json`.
- **Auto model routing** between Sonnet and Opus, with a one-time escalation from Sonnet to Opus on failure, and forced models through `/model`, `/opus` and `/sonnet`.
- **Slash commands and a model picker.** Claude Code commands, skills and custom commands run through the agent; Legion adds `/new`, `/model`, `/vm`, `/doctor`, `/agent` and `/clear`. Commands and models come from a cached, model-call-free catalog probe.
