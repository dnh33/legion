## [Unreleased]

### Added

- **Muster of ten more premade bots** (Inquisitor, Scribe, Archivist, Sentinel, Forgemaster, Exorcist, Preceptor, Herald, Assayer, Sculptor), each with a hand-painted, animated bust and portrait that follows the mascot layer contract, a persona (quips and idle verbs) and a role prompt. Seeded after Zealot, Builder and Scout, which are never changed. The Relic stays byte-identical.
- **Rooms** (comms bridge): group chats of 2 to 6 bots plus you, bot-to-bot direct messages, mention / manager / round-robin / all strategies, and guards for hops, budget, cycles and `@everyone`, with freeze and resume. Tools `bot_list`, `bot_send`, `room_post`, `room_read`, `room_list` and `handoff`. Messages from a bot carry no approval: a woken bot never runs looser than the strictest sender on the chain.
- **Lattice** (knowledge graph): a shared, traversable graph with search, neighbours, paths, recall and lint, Markdown vault import and export, and `kg_*` tools for every bot, plus a graph view.
- **BSV Dev Kit mode** (off by default): reveals the Assayer and a BSV knowledge pack. Knowledge only; no wallet, keys or signing.
- Title-bar view tabs (Chat, Rooms, Library) as icons, so the search box keeps its position.
- **Library** (see [docs/LIBRARY.md](docs/LIBRARY.md)): the Lattice grows into long-term memory for the bots. `kg_capture` (decision, mistake, pattern, project, idea in fixed shapes with a duplicate warning), `kg_wm_set` (a private 2,500-character working memory), `kg_supersede` and `kg_merge`, a 1,200-character per-run briefing, ranked recall, a deterministic episode note after long tasks that saved nothing, a nightly lint pass, and a one-way mirror of the bots' notes into `<vault>/legion/`.
- **Library safety**: every note carries an engine-derived trust (human, agent, untrusted). A run that touches the web, a shell or an outside tool is tainted for the rest of the task: its writes are untrusted and wait for you. Bots cannot edit your notes (their change becomes a proposal), change scope or delete shared notes; per-task write quotas; secret redaction; safety copies of the log.
- **Library screens**: Inbox (accept, edit then accept, reject, before/after diff of proposals, bulk accept that skips untrusted sources unless you tick it, filter by bot), Activity (the last writes with a 7-day Undo that says why it is disabled), amber pending count on the title-bar tab, trust and status badges, and in-place editing of a note (title, type, tags, body) and of a link (relation, note) in the Lattice detail panel.
- `PATCH /api/kg/edges/:id` to change a link's relation, note or weight (human only).
- **Token fix v1, review round** (findings F1 to F9 of the independent review). F1: an MCP-started run could still wake a peer above `ask` through `bot_send`, `room_post` and `handoff` (the hub took the ceiling from the sender agent's own approval), so on the seeded roster Zealot could wake Builder with Write/Edit allowed and a live shared note; the comms tools now carry the run's ceiling and every wake takes the strictest of agent mode, woken tasks and run ceiling (tests: seeded Zealot to Builder, full to full by all three tools, second hop). F2: the app chooses the port once, starts its core with `LEGION_PORT`, and pins the port and token for the window; `config.json` is not read again, so a bot editing `port` cannot redirect the window and the secret. F3: a token-only event stream no longer receives `room.*`, `comms.*` or `settings.*` events; the app reads its stream with `fetch` and the admin header (a browser tab keeps `EventSource` and `?token=`). F4: pid equality is replaced by a challenge: `GET /health?nonce=<hex>` answers HMAC-SHA256(secret, nonce) and the app releases the secret only to a core that proves it (a `node` shim with a different pid now works; a rogue echoing our pid does not). F5: under a ceiling `vm_exec`, `vm_claude` and `vm_desktop` need a card; reading `config.json` with `Read` stays possible and is documented. F6: an unanswered MCP card is denied after 10 minutes with a message to open the Legion app; documented for headless (Cowork) cores. F9: Restart core waits for the child's exit event instead of sleeping 500 ms.
- **Token fix v1, review round 2** (second independent review, SHIP WITH LISTED RESIDUALS). N2: a run under the `ask` ceiling (MCP-started or woken by one) could plant text for the next run you start from the app, through `kg_wm_set` or a private note with a `trigger:` tag; `kg_wm_set` is now refused under the ceiling and every private note such a run writes is stored untrusted (its shared notes wait in the Inbox), so it never reaches a briefing (tests: the reviewer's wm proof, the app-started run still writes both, a woken peer is capped too). N5: `/health`'s pid is only a claim, so before the app kills a core it did not start it checks that the pid owns the listener on the port (`netstat -ano`, `lsof`, `ss`); a squatter naming a victim pid is treated as blocked and nothing is killed. N3: the app starts its core in its own process group and stops the whole tree (`taskkill /T /F` on Windows), so a non-exec `node` shim leaves no orphan. F4r: the admin secret is 32 random bytes and a core ignores any shorter secret (minimum 32 characters). F6: the "Open the Legion app" message keys on the `ask` ceiling, so a peer woken by an MCP-started run gets it too. N6: `test/electron-emu/` runs the compiled Electron main with `electron` stubbed against a real spawned core (start, restart and rotation, config edit after launch, squatter, real foreign core replaced, non-exec shim, secret hygiene). Documented residuals in SECURITY.md: `legion_vm` over `/mcp` has no Legion card (N1), room text stays readable through a woken bot's task messages (F3b), and a port squatter is a denial of service that also sees the MCP token (F2r). Not verified: real Electron, and Windows (`taskkill`, real `netstat` output).
- **BSV mode v1** (still knowledge only; see [docs/BSV-MODE.md](docs/BSV-MODE.md)): a truthful pack (pack version 3: titles of design lessons start with `[Design]` and carry the `design` tag; unmarked lessons no longer state non-existent controls as fact). Lessons about controls that do not exist yet (spend caps, approval broker, audit log and Freeze, native arming, the Legion-owned bsv tool, VM boundary) are marked `props.built:false`, start with "Design, not built in v0." and sit at confidence 0.6; the new `bsv-status-today` lesson says what BSV mode is today; the contradictory Update/Correction paragraphs are folded into their nodes; the new `bsv-wallet-choice` lesson records the wallet plan (BSV Desktop first, HandCash beta second, never a monthly limit or auto-pay, two-stage approval). `kg_recall` takes an optional `scope`, which also restricts the linked notes it pulls in. A pack upgrade that never overwrites human edits: the version is stored on the index node, every seeded node carries a `seedHash`, and the toggle (or **Load BSV pack**) adds missing nodes, updates untouched ones and reports `skippedEdited`. A tripwire test keeps wallet, key and outbound-network code out of all of `src/` and `ui/src` (a short allowlist, evasions by concatenation and aliasing are caught; it is a static scan, see the docs). Review fixes: the pack version marker is written last so a crash mid-upgrade is repaired by the next start; the upgrade also runs at core start; what you edit (props, sources, type, scope too) and what you delete (nodes, links, relation changes) is kept, with `POST /api/kg/seed/bsv {restore:[ids]}` to bring a node back; bots can no longer link onto or rewrite pack links; the hidden Assayer is hidden on every surface (state, tasks, events, MCP, comms, rooms) and its queued runs are cancelled when BSV goes off; comms refuses a seed phrase; the UI reports what a pack load really did.
- **BSV mode v2** (still no spend tool; see [docs/BSV-MODE.md](docs/BSV-MODE.md) and [docs/BSV-WALLET-DESIGN.md](docs/BSV-WALLET-DESIGN.md)): `bsv_status`, a read-only wallet status tool for the Assayer (four harmless questions to a loopback address, mainnet wallet gives a warning and is never used) and `GET /api/bsv/wallet`; a pure, unit-tested policy engine (per-transaction, per-session and rolling-24-hour caps, recipient allowlist, output and fee limits, expiring in-memory arming, freeze, idempotent ids, injection guard) connected to no tool; an append-only, hash-chained audit log with a reader route and an Activity list; owner controls through the Electron app only (native secret on the core's stdin line 2, native confirmation dialogs, tray Freeze); a static interface (no animation: cyan testnet line, amber LIVE FUNDS frame and countdown only while armed, wallet-on-mainnet warning, Freeze chain button, BSV panel; status poll at most once a minute while visible and focused); the tripwire now allows wallet method names only in the one probe file and only its four allowlisted names; pack version 6 (lessons about controls that exist in part are `[Partly built]`, the status lesson and the Assayer preamble describe `bsv_status` truthfully). Not verified: the real BSV Desktop wallet (never contacted) and the native dialogs on a real desktop.
- **Library fix round 2**: a stale graph lock no longer blocks startup (staleness is detected), BIP-39 seed phrase detection, vault imports can no longer launder a note past the Inbox holds, a tainted run's workspace paths are taint-tracked, and `config.json` is written with mode 0600.
- **BSV final gate** (pack version 4): `bsv-status-today` and docs/BSV-MODE.md now state what approval means for the Assayer (in `ask` mode shell commands and file edits need approval; web fetch, web search and read-only tools run without a prompt; you can switch to `full`). A bot's final room reply that contains a seed phrase is replaced by a short notice and never stored; 64-hex transaction ids are no longer redacted in room messages (hex next to a key label still is); a purged pack tombstone stays deleted after a restart; the BSV preamble follows the `requires: 'bsv'` gate, not the id `assayer`; a new agent whose id is taken gets a short random suffix instead of `-2`, so a hidden agent's id is not revealed.
- **Token fix v1: two secrets** (R4.3). The MCP token in `config.json` now opens only `/mcp`, `GET /api/state|agents|catalog|tasks/:id(/wait)`, `POST /api/tasks`, `POST /api/tasks/:id/cancel` and the event stream. Every other route (approvals, settings, agent edits, VM routes, all `/api/kg/*` including reads, rooms, BSV, config, doctor, and any unknown path) needs `X-Legion-Admin`, a random per-launch secret that the Electron app writes to its core's stdin pipe and keeps in memory (never env, argv, a file, a log or `/health`; `/health` gains `admin:boolean`). A core started without the app (the MCP stdio bridge) is admin-closed; the app replaces an idle foreign core, asks when it is busy, and the UI explains a `403 admin_unavailable`. Tasks started through the MCP token (`legion_run`, `legion_continue`, `POST /api/tasks` without the admin header) run under an `ask` ceiling with origin `mcp`: a `full` agent runs in `default` mode with approval cards ("Asked by an MCP client"), `legion_continue` can no longer launder a ceiling away, and shared Library notes from such runs wait in the Inbox. Honest limit: a process running as your own user can still read Legion's memory, edit its files, synthesize clicks, read `config.json` (which holds `boat.apiKey` in plaintext) or call your BSV wallet directly; only a VM or a separate OS account stops that. BSV pack version 5 (the `bsv-safety-mainnet-armed-native` design note no longer claims the token reaches every route). Tests: helpers send the admin header by default (`asClient` opts out), plus `token-v1*.test.ts`. Not verified end to end: the Electron main process on Windows and the Cowork bridge.

- **BSV fix round 1** (independent review verdict: SHIP AFTER FIXES; there is still no spend tool). (1) A policy file changed outside Legion is no longer trusted: its SHA-256 is recorded in the audit log whenever Legion writes it, a file that differs, has no record, or is unreadable loads as default limits, an empty allowlist and frozen (the file is kept aside as `policy.json.tampered-<time>`), and while running the same check freezes the chain before any policy read, change or `bsv_status`. (2) Text that claimed more than the code gives was rewritten (the panel, the native dialogs, the Assayer's preamble, the docs and pack version 7 now say what is Legion's own code and that an agent's ordinary tools are outside it), and `test/bsv-hedge.test.ts` scans them for overclaiming phrases. (3) The audit log has a head anchor (`audit.jsonl.head`) so a truncated, emptied or replaced log is reported at the next start, a rotation no longer restarts the chain, and the rolling 24-hour spend window is rebuilt from every log file by entry time, not from the last 500 lines in file order. (4) There is no default wallet address; the owner types it and presses Connect (a native confirmation first), nothing is contacted at startup or before that, and every launch starts disconnected. (5) A "changed" report from the wallet can only disarm; it never raises a limit or resets state. (6) The tripwire folds escapes, `concat`, `replace`, `slice`, reversal and templates before matching names, and refuses computed calls, `eval`, `Function`, `Reflect`, computed globals and look-alike letters inside the BSV code. (7) A wallet version is shown only if it is valid semver. (8) The policy engine copies requests, answers and outcomes on the way in and the stored decision on the way out. (9) Freeze works on a headless core (bearer token; it can only stop things).

### Fixed

- The Assayer stayed reachable while BSV mode was off through `legion_run`, `legion_continue` and `legion_vm` (including `exec`), and the error text named it; the same lookup now refuses it as an unknown agent, and the HTTP routes that start a task or drive the VM of a hidden agent answer 404.
- A plain re-seed of the BSV pack (the Lattice button, or toggling BSV off and on) overwrote human edits of pack nodes, and a human note written to scope `bsv` first stopped the pack from ever loading.

### Changed

- The title-bar tab that opened the Lattice is now called Library and holds the Lattice, Inbox and Activity. The graph view itself is unchanged.
- The light-theme title-bar count badge uses white text (it was near-black on dark amber).
- `mcp__legion__ask` and `tell` now apply the same approval ceiling as rooms: an agent started through the bridge is never more permissive than its caller. Agents switched off (Assayer while BSV mode is off) are neither listed nor reachable through the bridge.

### Removed

- The `npm run video` script and the README trailer image: both pointed at files that are not in the repository.

## [0.1.0] - 2026-09-30

First public release.

### Added

- **Legion Core**, a local Node service bound to `127.0.0.1` with a bearer-token HTTP API, a server-sent events stream and an MCP endpoint.
- **Electron desktop app** with a tray icon, single-instance lock, sandboxed renderer, dark and light themes, and bundled fonts.
- **Agents** built on the Claude Agent SDK, using the Claude Code account you are signed in to (or an API key). Three defaults (Zealot, Builder, Scout) plus custom agents with their own system prompt, model, approval mode and working directory. Claude Code settings, MCP servers and claude.ai connectors are inherited, and extra MCP servers can be added in `config.json`.
- **Auto model routing** between Sonnet and Opus, with a one-time escalation from Sonnet to Opus on failure, and forced models through `/model`, `/opus` and `/sonnet`.
- **Slash commands and a model picker.** Claude Code commands, skills and custom commands run through the agent; Legion adds `/new`, `/model`, `/vm`, `/doctor`, `/agent` and `/clear`. Commands and models come from a cached, model-call-free catalog probe.
- **Inline approvals** with `ask`, `auto-edits` and `full` modes, Allow/Deny cards and `A`/`D` shortcuts, and auto-deny after ten minutes.
- **On-demand boat.dev VMs per agent**: start, exec, file access, `vm_claude` (Claude Code inside the VM), desktop link, live screenshot preview, and automatic idle stop.
- **MCP orchestration** for Claude Code (HTTP) and Cowork or Claude Desktop (stdio bridge) with nine tools: `legion_list_agents`, `legion_models`, `legion_create_agent`, `legion_run`, `legion_continue`, `legion_status`, `legion_cancel`, `legion_vm` and `legion_recent_tasks`.
- **Doctor** checks for Node, config, Claude sign-in, boat.dev and the workspace.
- **The Relic**, a hand-painted animated mascot with nine expressions, plus the Expression Lab page and a mascot layer contract for adding others.
- **Windows installer** (`setup.cmd`) that installs per user under `%LOCALAPPDATA%\Programs\Legion`, with shortcuts, in-place updates and an uninstaller.
- Command palette, keyboard shortcuts, task history per agent, and cost and turn tracking.
