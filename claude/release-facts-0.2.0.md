## FEATURE DETAIL: BLENDER (use this for the Blender section; it is specific on purpose; sourced from the product docs and plans, not tried on a real Blender yet)
What it is: the Sculptor is one of the 13 bots. It builds 3D scenes by writing Python scripts that run in REAL Blender. There are three places a script can run; Legion picks by what is set up and says which one it used:
1. THIS COMPUTER, headless (default when Blender is found): Legion starts Blender in the background (no window) with its own settings, one folder per task, a scrubbed environment, a time limit, and everything it wrote is checked on the way out. Needs Blender 4.2 or newer. Honest limit: Legion checks the script before running it, but that check is a filter, not a sandbox; the script runs with the user's own rights, so every script shows an approval card first and the user should read it.
2. A cloud VM (boat.dev, the user's own account): the isolated option; Blender runs inside the agent's VM.
3. LIVE: the user's own open Blender, through an add-on (the official Blender MCP add-on, needs Blender 5.1 or newer; or the community add-on, works with older versions). Live runs touch the user's open scene, so Legion backs the scene up before the first live script.
Getting Blender: if Blender is not installed, Settings can fetch ONE pinned official portable Blender (5.2.2 LTS for Windows x64, about 386 MB; checked against its published SHA-256 before it is unpacked; only after the user presses the button and approves a card that shows the address, size and hash) or link to blender.org/download for the full app. Legion never installs Blender silently. The in-app fetch button ('Get Blender for Legion', in Settings, Blender) works on Windows only in 0.2.0; on macOS and Linux the user installs Blender themselves (the 'Get full Blender' button is just a link). Once installed, the button is greyed out and shows where the copy lives and how to remove it (delete the folder).
First use: a one-time chooser (this computer / cloud VM / my open Blender / decide each time). The Sculptor's instructions tell it when each fits.
Optional, OFF by default: 'use both add-on backends at once' (official main, community second, on two separate local ports) and asset downloads (Poly Haven models and textures; each download needs its own approval card; the run becomes tainted; files land only in the task's folder; each asset source is off until the user turns it on; Poly Haven credit shown).
What comes out: files the script exports (an allow-list of file types, size limits); .blend files are quarantined, not opened automatically.
Not done: tried on a real Blender (every real-Blender check is still to run), a tested recipe for sculpt brush strokes (the Blender Python API has them; the recipe needs a real Blender to test).
The test harness's fake Blender is a developer stand-in and must never be described as a Legion feature.

## FEATURE DETAIL: PROJECT BOARD (owner decision 2026-10-03: IN 0.2.0, ON BY DEFAULT). Status: SHIPS (merged and test-gated 2026-10-03; the approvals/taint bug found at the merge is fixed with a test proven red first). Claim it as 'Built and tested, not yet tried by a real user on a real PC'.
What it is: inside a Project, a work board for the owner and the project's agents. Work items have a title, description, status (backlog, doing, review, done, blocked), an assignee (one member agent or the owner), an optional due date, a priority, labels, and links to the agent runs, rooms and notes that worked on them, plus an activity trail. Board (columns, keyboard and drag) and list views; an Inbox for items a bot proposed.
Run an item: the owner presses 'Run this item': the assigned agent starts a task with the item's text and the project instructions (same approval cards as any run); the item moves to 'doing', the run is linked, and when the run ends the item moves to 'review' with the result linked. Only the owner marks an item done.
Agent access (the owner asked for this): member agents can create live items, edit them, move and reorder them, claim or assign them, label them and add notes, through a small tool. Guards that remain: items created by a run that touched outside content (the web, a shell) are marked untrusted; an agent cannot touch another project's items; the exact remaining owner-only rules are in the product's docs/PROJECT-BOARD.md: take them from there once merged, do not guess. Token clients (MCP/curl) are read-only. The board never runs anything by itself: no schedules and no automation rules.
Project as a context layer: each run in a project starts with the board digest and the titles and ids of the project's five most recent project notes; notes of other projects, private notes, untrusted notes, notes from tainted runs and automatic episodes are never included. 'Save what we learned': after a run, the owner can save a human-written note into the project (shown to that project's agents only, linked to the item); it refuses an archived project, an empty note, and any text that contains a seed phrase or private key; if the run read outside content, it warns the owner first.
Status: tested against fakes and demo data, not yet tried by a real user on a real PC. Not done: schedules and automations, unlinking notes by agents, the MCP side stays read-only.
