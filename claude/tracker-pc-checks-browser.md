# Browser tool: checks only the owner's Windows PC can do

Built-in browser = headless Edge or Chrome already on the PC, driven by Legion's own CDP client (`claude/plan-browser.md`). Nothing here was run in a cloud session: the tests use a fake browser script and a fake CDP server. Safety class for all: none (use a harmless public page you control), unless noted. Do not call the browser tool verified until each is recorded as passed.

## Checks for 0.2.0

- **BR15 Real Edge starts** (Windows 10/11). Settings, Browser: switch it on; the status line shows "Browser: Microsoft Edge <version> at C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe", read from the file. Press **Open test page**. Expected: all four lines say OK (browser started, test page loaded, JavaScript ran, forbidden request refused); no Edge window appears; a `legion-browser-*` folder exists in %TEMP% during the run and is gone afterwards; "Last run" shows the time and "worked". Then run a task that opens a harmless page: the result says "Browser: Microsoft Edge <version> (headless)". Evidence: the Settings lines, the result text, `dir "%ProgramFiles(x86)%\Microsoft\Edge\Application"` (version folder names). If Edge does not start with Legion's reduced environment, tell the builder (it may need more variables).
- **BR16 Guards on a real Edge** (a page YOU control): redirect to `http://127.0.0.1:<some other port>/`, a two-hop redirect chain ending on a private address, a sub-resource image from a private address, a download link, `window.open`, a `file:` link, a `data:` navigation. Expected: each is refused or blocked and no content is returned; no file appears in Downloads; no extra window. Also confirm a `browser_open` of `http://127.0.0.1:<port>/` is refused with the default settings (do not use the wallet port).
- **BR17 Gaps to measure** (not expected to pass): a page script opening a WebSocket to a private address; WebRTC; a service worker; a DNS-rebinding name (a name you control that flips between a public and a private address). Record what happens; the plan lists these as not protected. Also: do `--block-new-web-contents` and `--deny-permission-prompts` do anything on this Edge (try `window.open` and `navigator.geolocation`)?
- **BR18 Kill**: cancel a task with a page open, then quit Legion with one open. Expected: no `msedge.exe` that Legion started is left (judge by PID: `tasklist /fi "imagename eq msedge.exe"` before and after; never kill by name). Your normal Edge windows are separate processes.
- **BR19 Your own Edge is untouched**: open Edge normally before and after; its profile, tabs and logins are unchanged; nothing from them was used, and no file in your real Edge profile changed.
- **BR20 Chrome and Brave** (if installed): set the path in Settings ("Use this browser", a confirmation dialog appears, Cancel is the default; Cancel changes nothing), repeat BR15, then press Automatic.
- **BR21 Native dialogs** (safety class: native dialog): (a) "Use this browser" shows the program path and says it runs with your user rights; Cancel changes nothing; Confirm saves. (b) "Allow local addresses" with a port shows the ports and says it lasts until restart; after a restart it is off again. Evidence: a screenshot of each dialog. The Settings page alone (browser dev tools) cannot make the same change.
- **BR22 Missing or too-old browser**: set a wrong path (dialog) or rename `msedge.exe` temporarily. Expected: the status line says "No Edge or Chrome found: install one or set a path."; "Open test page" and an agent's `browser_open` fail with that plain message and start nothing; undo it afterwards.
- **BR23 Loopback only**: while a task has a page open, `netstat -ano | findstr LISTENING` shows the browser's debugging port on `127.0.0.1` only, not `0.0.0.0` or `[::]`. Note the port number changes per task.
- **BR24 No leftovers**: after several runs, `%TEMP%` holds no `legion-browser-*` folders and Edge's own user data was not touched.
